**Unresolved n8n execution bookkeeping defect:** a read-only query of n8n's own `execution_entity` table after these runs found 30 webhook executions with `status=running` and no `stoppedAt`, including B execution IDs 137, 139, 142 and C IDs 138, 140, 141, 143. The app's `workflow_executions` records and business side effects are terminal/successful, but n8n itself has not marked those webhook runs terminal. Their persisted `execution_data` has an empty `runData` snapshot, so it cannot independently prove a completed node-by-node run. Workflow A's manual n8n execution is distinct and terminal. This is **PARTIAL** workflow evidence and a P1 reliability/observability risk, not a claim that n8n B/C finished successfully. Do not use n8n's current execution counts as an operational success metric until this is reproduced and fixed in an isolated n8n test environment.
