## Test-harness and environment findings (not product bugs)

- The first real browser fixture used `@example.invalid`; the validator correctly rejected all three emails. The fixture was corrected to safe `@example.com` addresses. No email was sent. A failing screenshot/trace and a later passing run demonstrate the correction.
- OrbStack's Docker socket disappeared with host disk nearly full. Local worker/dispatcher lost PostgreSQL connectivity and exited; the LocalStack bucket was absent after restart. We removed only the ignored, reproducible `.build/m8` artifact and Next development caches (about 93 MiB), restarted OrbStack and ran `make up` plus `make s3-init`. Database volumes survived. This is an operational limitation; a lost emulator object cannot be reconstructed from a batch record, so re-upload is required.
- A real n8n import deactivated Workflow B/C. Publishing both workflows and restarting n8n restored webhook operation. This is documented setup behavior, not a silent green execution.

## Confirmed unresolved: n8n webhook executions never become terminal (P1)

After the full Chromium upload and signed-dispatcher runs, query the isolated n8n database's `execution_entity` table. Thirty B/C webhook rows were still `running`, including recent IDs 137–143, with null `stoppedAt`. App-side workflow rows are `succeeded` and match/notification side effects exist, but n8n's own execution record does not close. Its saved `runData` is empty. This impairs execution visibility, retention and possibly recovery after a crash. The cause is not yet isolated: early `Respond to Webhook`, `saveDataSuccessExecution=none`, or n8n 2.43.5/PG16 behavior are candidates, not established diagnoses. No workflow change was made without a reproducible isolated fix. Before deployment, reproduce on a disposable n8n database, enable success-run evidence, identify the cause and add a terminal-state assertion to the real webhook test. Do not manually mark these rows successful.

No visual-layout defect was confirmed, so there is no invented before/after visual fix. Desktop/mobile screenshots and overflow checks are retained as QA evidence.
